# Decisiones Arquitectónicas (ADR)

| ID | Decisión Arquitectónica | Driver Relacionado | Justificación | Resultado |
| :--- | :--- | :--- | :--- | :--- |
| **ADR-001** | **Adopción de Monolito Modular en lugar de Microservicios Distribuidos** | DA04 - Baja latencia; DA06 - Mantenibilidad; RC04 | Al abarcar exclusivamente el dominio de Citas Médicas, dividir en microservicios introduce sobrecosto de red, transacciones distribuidas complejas (Saga) y carga operativa excesiva. Un monolito modular mantiene límites claros entre dominios sin la penalización de latencia inter-servicio. | Código unificado en un solo repositorio; módulos desacoplados listos para ser extraídos a microservicios independientes si el hospital lo requiere en el futuro. |
| **ADR-002** | **Arquitectura Hexagonal (Puertos y Adaptadores) por Módulo** | DA06 - Mantenibilidad; DA08 - Estándares | Separa la lógica de negocio pura (Dominio y Casos de Uso) de las dependencias tecnológicas (controladores web, bases de datos, pasarelas de SMS, clientes Redis). | Permite probar el negocio sin levantar bases de datos ni servicios externos; simplifica el reemplazo de tecnologías de infraestructura. |
| **ADR-003** | **Estrategia Anti-Doble Agendamiento con Bloqueo Temporal (Slot Locking)** | DA03 - Consistencia; AC04 - Integridad | Durante picos de agendamiento (7:00 a.m.), varios pacientes compiten por el mismo cupo. Se requiere garantizar atomicidad sin bloquear toda la tabla de citas. | Implementación de candado en Redis con TTL de 5 minutos al iniciar la reserva, seguido de confirmación transaccional en PostgreSQL con `SELECT ... FOR UPDATE`. |
| **ADR-004** | **Capa de Caché de Disponibilidad en Redis con Invalidación por Eventos** | DA02 - Alta concurrencia; DA04 - Latencia | El 85% del tráfico en picos son consultas de horarios disponibles. Golpear la base de datos para cada lectura colapsaría el pool de conexiones. | Respuestas de disponibilidad servidas desde Redis (< 15 ms). Al confirmarse o cancelarse una cita, se emite un evento interno que invalida la llave del médico/fecha afectada. |
| **ADR-005** | **Mensajería Asíncrona para Notificaciones e Integraciones (RabbitMQ / Redis Streams)** | DA05 - Desacoplamiento asíncrono; AC07 - Tolerancia a fallos | Enviar mensajes por WhatsApp, SMS, correo o sincronizar con MINSA/SIS toma entre 500 ms y 3 segundos por solicitud y puede fallar por problemas de terceros. | La confirmación de la cita responde inmediatamente al usuario (< 500 ms) y delega la tarea a una cola asíncrona procesada por *workers* dedicados con reintentos automáticos. |
| **ADR-006** | **Persistencia Principal en PostgreSQL con Réplica de Lectura** | DA01 - Disponibilidad; DA03 - Consistencia ACID | Requiere soporte estricto de transacciones relacionales ACID, índices avanzados para rangos de fechas/horas y alta fiabilidad probada. | Base de datos primaria para escrituras y reservas; réplica de lectura para consultas de reportes y tableros estadísticos pesados. |
| **ADR-007** | **Escalabilidad Horizontal Stateless mediante Contenedores y Balanceador** | DA01 - Disponibilidad; DA02 - Alta concurrencia | El servidor de aplicación no guarda estado en memoria de proceso (las sesiones radican en tokens JWT o Redis). | Permite levantar 2, 4 o N réplicas del contenedor de la aplicación detrás de un balanceador Nginx / Cloud Load Balancer según la demanda horaria. |
| **ADR-008** | **Seguridad por Diseño: JWT + RBAC + Auditoría Inmutable** | DA07 - Seguridad y privacidad; RC01 | Cumplimiento de la Ley N.° 29733 de Protección de Datos Personales y protección de endpoints administrativos y médicos. | Tokens JWT firmados, control de acceso granular por rol (Paciente, Admisión, Médico, Administrador) y tabla de auditoría append-only para trazabilidad forense. |
| **ADR-009** | **Modelado de Entidades Basado en HL7 FHIR (Recursos Appointment y Slot)** | DA08 - Interoperabilidad; RC02 | Facilita la adopción futura de otros módulos hospitalarios (Historia Clínica Electrónica, Laboratorio, HIS MINSA). | Entidades de dominio modeladas como `TurnoDisponible` (Slot), `AgendaMedica` (Schedule) y `CitaMedica` (Appointment), facilitando exportación nativa a JSON FHIR. |
| **ADR-010** | **Patrón Circuit Breaker y Cola de Mensajes Muertos (DLQ)** | AC07 - Resiliencia; DA05 | Si las APIs del SIS o de WhatsApp sufren intermitencias, el sistema no debe degradar sus hilos ni perder notificaciones pendientes. | Apertura de circuito ante fallos continuos y reencolamiento en DLQ con reintentos exponenciales para envío garantizado. |
